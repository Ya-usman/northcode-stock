Serveur local (compilation de production) :
  NOTCHPAY_PUBLIC_KEY=pk_test_factice npm run build && NOTCHPAY_PUBLIC_KEY=pk_test_factice npx next start -p 3000

Lancer les suites courantes (l'une après l'autre, journaux dans tests/e2e/out/, résumé dans out/resume.log) :
  bash tests/e2e/run-local.sh                  # suites par défaut
  bash tests/e2e/run-local.sh stock-nav lots-ux   # suites choisies
Les repères du compte vitrine (out/vitrine/) sont relus en base, en lecture seule, à chaque lancement.

Contrôles en ligne après un push (lecture seule, Marché Soleil) : node tests/e2e/prod-smoke-<lot>.js

Protections permanentes (lib/capture.js, lib/session.js) :
- CAPTURE_BASE est obligatoire : aucune adresse par défaut.
- Hors serveur local, CAPTURE_PROD_READONLY=1 est exigé (contrôle en ligne de pure lecture).
- Toute écriture du navigateur (sauf l’ouverture de session) est bloquée et reçoit 204, en local comme en ligne.
  Un test qui doit lire ce qui part déclare ses propres routes ; rien ne passe jusqu'au serveur.
- Service worker bloqué : aucune vente hors ligne ne peut être synchronisée par un test.
- Horaires d'ouverture neutralisés dans le navigateur du test seulement (Boutique Alpha est fermée la nuit).
- Écritures réelles : uniquement Boutique Alpha, sur des objets « TEST », nettoyés par le parcours normal.
- Marché Soleil (compte vitrine) : lecture seule. Il sert aussi aux démonstrations : ne jamais figer ses chiffres
  dans un test, les relire en base.

Tests à ÉCRITURE RÉELLE sur Boutique Alpha — à lancer seulement sur accord explicite :
  bash tests/e2e/run-write.sh     (stock-reserved, product-detail, inventory-v2, lot2-scope ; bilans dans out/write-resume.log)
Mode ÉCRITURE (lib/write-mode.js), activé dans le code de chaque test, jamais par une variable seule :
- serveur local uniquement ; adresse distante ou CAPTURE_PROD_READONLY → refus immédiat, avant toute connexion ;
- avant la première écriture, la base confirme que la cible est Boutique Alpha (identifiant, nom, propriétaire d'essai) ;
- navigateur : seules les routes déclarées par le test passent, et seulement si la requête vise Alpha ;
  encaissement et synchronisation des ventes toujours bloqués ; une requête vers une autre boutique n'est jamais envoyée ;
- référence unique par exécution (W.RUN) pour tout ce que le test crée ;
- nettoyage : uniquement les lignes NOUVELLES d'Alpha qui citent l'exécution, supprimées une à une par identifiant ;
  jamais de suppression large ;
- photo complète d'Alpha avant / après : bilan « lignes créées / supprimées », aucune ligne préexistante supprimée ni
  modifiée, aucune trace restante — sinon le test échoue.
